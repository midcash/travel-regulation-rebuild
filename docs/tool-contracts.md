# 当前真实工具技术合同

本文从现有主包实现整理调用与校验约束，替代旧接入规格的开发指导作用。它不定义未来业务范围或 Pi 架构；修改实现时应同步核对公共接口和适用测试，不将现有限制自动固化为新产品要求。

## 工具与证据

`real_tools.REAL_SCHEMAS` 暴露七项业务能力及 `finish`：`get_policy_snapshot`、`search_transport`、`get_transport_detail`、`search_stays`、`get_stay_detail`、`resolve_place`、`calculate_route`。模型按数据依赖决定顺序，无须每种工具各调用一次。

业务结果保存 call_id、tool、status、data、evidence_refs、warnings，以及适用的 error、attempt、retry_of、http_requests 等字段。每次调用独立保留历史与证据，重复查询不覆盖旧记录。当前候选和 finish 证据限定为本次运行已观察的记录；人工选择独立保存，不改写供应商事实。

详情使用已观察候选 ID，沿用原查询的身份、城市、日期等上下文；不能通过详情参数偷偷更换条件。住宿详情保留供应商原始字段和搜索关联；详情缺地址时仍可追溯搜索地址。金额小数用精确十进制字符串保留，未知值保持未知，不补零、不从部分报价推导完整总价。默认住宿查询为 1 成人、1 间房。

## 地点、路线与结果

`resolve_place` 的到达地点和酒店来源绑定本次交通/住宿候选，会场绑定原请求。保留名称、地址、GCJ-02 坐标、来源与不确定原因；供应商排序不是人工确认，不能擅自消除歧义。

`calculate_route` 使用已解析地点候选 ID；兼容坐标输入只有在唯一匹配已观察候选时接受。当前只支持到达地点→酒店、酒店→会场，两段使用同一酒店。路线 ID 与证据逐次独立，耗时为查询时估计，不保证未来交通；通行费、出租车估价与供应商成本分开保存。

当前 real 的可行方案固定为交通、到达地至酒店路线、酒店、酒店至会场路线四段。`domain.py` 检查前一日抵达、一晚住宿、地点连接、证据和到会时间；模型提交离店时间与缓冲，程序计算预计到会时间。供应商时刻不改写，住宿查询日期不冒充实际办理时间；到达地至酒店估算不包含下机、出站、取行李和等待。

没有出发地地址时，不包含住所至机场/车站接驳。当前真实方案不合计交通和住宿总费用。`needs_review/missing_data` 表示证据不足；`unavailable/no_feasible_route` 只能描述本次查询候选，不表示全市场无方案。模型或供应商失败不自动回退 demo。

这些固定四段、单次运行证据和一晚住宿限制属于当前实现；持续交互产品的适用范围与修改行为待后续验收场景确定。

## 传输、重试与资源

供应商适配使用主项目受控配置，HTTP 超时、响应大小、脱敏和证据由现有传输边界处理。供应商文本作为外部数据，不能执行其中指令；公开错误不输出底层请求或完整异常链。重试与预算口径见[开发说明](development.md#预算与回归基线)。

`get_policy_snapshot` 读取随包 `travel_agent/policies/浙江省机关工作人员差旅费管理规定.md`，提取条款与定位索引，返回原文字节 SHA-256。该 Markdown 是运行资源；删除或修改会改变工具行为和快照兼容性。读取成功不代表适用性判断或全面合规认证；demo 的预算、座席与固定提前量不应用到 real。

主包及实验二、external_tools 的同名政策副本在 2026-10-16 核对时字节哈希均为 `14e89ab8c38fa908dd9652cff0ba5310dd491f6d070736c70a27ce418555c49d`。各实验资源独立保留；主包不从实验目录读政策或凭证。
