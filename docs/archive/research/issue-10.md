[Issue #10](https://github.com/midcash/travel-regulation-rebuild/issues/10) 标题为「[09] 完成重试恢复、执行预算与最终联调验收」，状态为 OPEN，无评论。它要补齐并验收业务流程的可靠性：失败后正确重试、人工介入后恢复、执行预算内运行，并通过真实模型和真实 API 验证页面到结果的完整链路。

正文说明本地已存在步骤、工具、模型时限、活跃时间和 Token 上限；HIL 暂停恢复会保留计数、预算、历史证据。但这些能力尚未完成最终验收，已有提交 1bd2e63 和工作区实现不能视为已推送、合并、发布及验收完成。[来源：#10](https://github.com/midcash/travel-regulation-rebuild/issues/10)

验收要求包括：

- 分别记录工具操作、HTTP 请求和重试，并计入预算；航班第三次、酒店第二次成功的固定结果场景须在预算内完成。
- 持续失败或预算耗尽时明确结束；使用单一重试边界，鉴权错误不盲目重试。
- 动态评测检查时间、地点和证据，线上不固定价格；隔离安装能读取随包政策，不依赖实验配置。
- 至少完成一次真实模型和真实 API 到页面的成功联调，并由独立上下文对抗复查时间衔接和证据篡改。

以上验收点均来自 [#10 正文](https://github.com/midcash/travel-regulation-rebuild/issues/10)。
