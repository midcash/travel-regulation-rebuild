# GitHub #9：页面自然语言请求

页面新增自然语言请求选项，并保留原结构化表单。解析结果沿用现有结构化请求与规划/Trace 主链路；当前解析范围覆盖本工单示例所需的会议日期和时间、出发城市、会场、飞机/火车偏好及一晚住宿。缺少必需信息或提出不支持的住宿晚数时，页面会显示可更正的错误。

## 复现

固定测试时钟 `2030-09-12T09:00+08:00` 下提交：

```text
下周六早上 9 点在三亚湾红树林国际会议中心开会，从杭州出发，提前一晚抵达，乘飞机并住一晚。
```

页面解析摘要应显示 `2030-09-21 09:00`、飞机、前一日抵达、一晚住宿及暂按 1 人 1 间房。自然语言提交时仅捕获一次上海时区时间，并将捕获值写入 Trace；相对日期不会在暂停恢复时重新解析。过去的会议或前一日到达/入住日期在创建任务前返回 400，不调用模型或供应商。真实工具还会拒绝早于该请求日期的交通出发日和酒店入住日。

本地手工运行：

```powershell
.\.venv\Scripts\python.exe main.py
```

选择“真实工具”及已配置的 DeepSeek/Ollama，在“业务场景 / 输入方式”选“自然语言请求”并提交上述文本。结果及调用链显示在该次运行的 Trace；默认 SQLite 文件为 `artifacts/observability.sqlite3`，也可在页面运行记录中打开。
