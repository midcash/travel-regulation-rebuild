# 真实差旅工具接入规格

日期：2026-09-10

状态：业务范围、必要适配与测试入口方案均已获用户确认。本文仅定义后续实现，不表示已完成集成或验收。

2026-09-11 增量约定：用户已另行授权 [HIL 主链路兼容约定](hil-compatibility-contract.md)的分阶段实现。该增量允许共享执行内核、交互持久化及必要页面入口；下文关于保留原循环/不引入人工交互的范围限制，以此有限例外补充。本文的真实工具名称、参数、证据、业务目标与原工单验收要求保持有效。

## Problem Statement — 问题

当前主链路能够通过模拟工具生成固定行程，但无法利用真实航班、酒店、地点和路线数据完成用户的差旅安排。实验二已提供真实业务工具，并留下杭州至三亚的成功查询记录；需要将这些能力接入现有 Agent 主链路。

用户本阶段只要求真实数据能够进入完整执行流程，核心业务目标是提前一晚抵达目的地、住宿一晚、准时或提前抵达会议地点。无需最优推荐、完整费用、预订能力或政策业务优化。

“执行完成”与“方案可行”分别验收：真实工具调用后正常输出资料不足，也属于正确执行结果；只有证据足够且时间、地点满足需求，才允许输出可行方案。一次资料不足不能替代成功场景的验收。

## Solution — 解决方案

将实验二当前版本的七个业务工具及必要底层实现迁入主链路所属包，在主链路目录形成独立维护的工具代码。复用指迁移并适配实现，不是运行时导入实验目录。允许 LLM 按需求选择工具、参数和调用顺序。以工具层为主要修改范围，保留现有 Agent 循环、可观测性与页面结构；对输入、工具调用协议、行程输出、校验和执行预算做必要适配。

用户输入会议信息及出行偏好后，系统查询交通和住宿候选，按需获取详情、解析地点并查询路线，生成一条有本次工具证据支持的安排。工具原始事实与规划产生的时间、缓冲必须区分。关键数据不可用时明确结束并保留原因，不补造事实，不静默回退到模拟数据。

### 代表性业务场景

固定测试时钟为亚洲/上海时区 2026-09-10。用户说“下周六早上 9 点在三亚湾红树林国际会议中心开会，从杭州出发，提前一晚抵达，乘飞机”，解析为 2026-09-19 09:00 开会，2026-09-18 抵达三亚并住宿一晚。未提供人数、房间数时暂按 1 人、1 间房，并在输出说明。

已有查询样例：HU7386 在 9 月 18 日 16:05 从萧山机场 T3 起飞、18:55 抵达凤凰机场 T3；海韵度假酒店住宿日期为 9 月 18—19 日；机场到酒店路线约 21 分钟，酒店到会议地点约 16 分钟。8:00 离开酒店可形成早于 9:00 抵达的规划。

这些班次、酒店与报价只作为历史证据和离线样例，线上验收不要求再次返回相同商品。8:00 出发、20:00 左右入住、8:30 左右到场均属于规划安排，不能冒充供应商原始返回。

## User Stories — 用户故事

1. 作为出差用户，我希望输入会议日期、时间和地点，以便系统以到会要求安排出行。
2. 作为出差用户，我希望表达“乘飞机”和“提前一晚抵达”，以便系统保留我的出行约束。
3. 作为出差用户，我希望相对日期结合当前日期和时区转换并明确展示，以便核对实际出行日期。
4. 作为出差用户，我希望系统查询真实航班，以便看到实际返回的时刻和机场。
5. 作为出差用户，我希望系统按需查询航班详情，以便使用正确航站楼和必要票价信息。
6. 作为出差用户，我希望查询指定入住和退房日期的酒店，以便住宿与会议日期衔接。
7. 作为出差用户，我希望酒店详情和地点查询能够关联同一家酒店，以便接驳路线正确。
8. 作为出差用户，我希望会场匹配结果显示名称和地址，以便识别同名或错误地点。
9. 作为出差用户，我希望查询到达机场到酒店的路线，以便安排前一晚入住。
10. 作为出差用户，我希望查询酒店到会场的路线，以便决定次日出发时间。
11. 作为出差用户，我希望系统比较预计到达时间与会议开始时间，以便拒绝迟到方案。
12. 作为出差用户，我希望供应商事实与规划预估有所区分，以便理解到达时间的依据。
13. 作为出差用户，我希望缺少费用时仍能获得有依据的时间安排，以便不被非必要报价阻断。
14. 作为出差用户，我希望工具失败或地点不明确时收到真实说明，以便知道方案为何未完成。
15. 作为项目维护者，我希望使用当前指定政策文件作为唯一政策来源，以便不再隐式应用演示规则。
16. 作为项目维护者，我希望模型自行选择必要工具并可在预算内重试，以便真实接口流程能够完成。
17. 作为项目维护者，我希望输出引用本次调用证据且不被重复查询覆盖，以便追溯方案来源。
18. 作为项目维护者，我希望保留现有观测和评测入口，以便定位接入失败而无需重建系统。

## Implementation Decisions — 实现决策

### 修改边界

- 以工具层接入为主。代码量需要时建立工具包，按实际职责拆分，不引入通用插件框架、调度器、工作流引擎或新的架构层。
- 必要适配覆盖请求解析与参数传递、工具说明和分发、执行循环边界、结果序列化、行程输出与校验、现有页面字段及评测断言。不得夹带无关重构。
- 保留原有观测、追踪、执行预算与页面结构。模拟数据只用于明确标记的离线验证，不作为线上失败回退。
- 主链路工具、请求及证据处理、配置和政策读取独立维护；不得直接或间接导入任一实验包，不通过修改模块搜索路径或动态加载绕过此边界。实验二代码与资源保持不变，后续主链路升级不自动同步回实验二。
- 当前实验二已自包含配置、Capture、七工具及政策读取，旧的分层修正已合并。迁移以该版本为基准，不再从实验一拼装依赖，也不复制过时的修正继承链。
- 将同一政策原文随主链路发布并保持初始字节哈希一致；配置从主项目环境或明确配置加载，证据写入主项目运行产物位置。主链路不得依赖实验目录的密钥文件、政策路径或历史结果。
- 实验入口的固定候选选择、调用顺序和运行脚本不迁入主链路。必要的日期约束与有界重试由主链路适配承接，不另建一套实验编排流程。

### 工具协议与数据

- 暴露 search_transport、get_transport_detail、search_stays、get_stay_detail、resolve_place、calculate_route、get_policy_snapshot 七项能力，复用实验二实现。旧名称兼容只有在不会隐藏必要参数或限制调用时才保留。
- LLM 按需决定调用哪个工具。取消固定顺序、各调用一次及必须查询全部工具才能结束的演示约束；保留实际数据依赖和有界执行。
- 详情使用已获得的候选标识，路线使用有来源的地点坐标。地点候选的名称、地址及关联证据不得在适配中丢失。
- 工具结果保留状态、数据、警告、证据引用和错误信息。重复查询及不同路线采用本次调用范围内唯一的证据标识，避免覆盖。
- 保留日期、时区、金额精度和未知值。未知费用不填零；路线通行费不能当作出租车价格。部分报价之和应说明包含和排除的项目。
- 将异步工具接入现有执行入口，正确管理客户端生命周期、整次调用超时及 JSON 序列化，不重写整个 Agent 框架。
- 复用受控配置与依赖方式；日志不泄露密钥，不直接暴露底层请求或完整异常链。

### 请求与行程

- 请求能够保留出发地、目的地、会议地点、会议时间、交通方式及提前住宿要求。既有结构化输入保持可用；自然语言输入只补足本场景所需的日期和偏好传递，不建设通用对话管理系统。
- 相对日期使用运行时当前日期和亚洲/上海时区，输出明确日期。2026-09-19 仅属于固定测试时钟对应的样例，不写成生产常量。
- “提前一晚抵达”要求在会议前一日抵达目的地并衔接一晚住宿，不再要求前一日 18:00 后起飞。前日下午起飞有效；会议当天凌晨抵达不满足本场景。
- 允许模型基于真实航班时刻、路线耗时和住宿日期提出出发时间与缓冲，并在结构化结果中保留计算依据。最终文本不得绕过结构化校验。
- 校验真实交通时刻、住宿日期、地点连接、各段时间顺序，以及最终预计到达不晚于会议开始时间。有明确提前量时一并校验；示例中的 30 分钟不升级为统一政策。
- 不改写供应商交通时刻；不将住宿查询日期投影的零点当成酒店实际办理时间。酒店入住安排可为明确标注的规划估计。
- 驾车耗时是查询时估计，不保证未来路况。地点匹配未人工确认时如实保留状态；存在影响路线的明确歧义时不能直接宣称方案已确定。
- 出发地具体地址未提供时，不计算杭州住址到机场的路线，并说明这段尚未包含。

### 政策、结束状态与预算

- 唯一政策来源为迁入主链路的《浙江省机关工作人员差旅费管理规定》原文副本，内容以当前实验二指定文件为准。保持该文件业务内容，本阶段不新增或优化规则、不开展适用性或报销结论推理。
- 不补回旧演示政策的预算、二等座和固定提前量字段；不因缺少这些旧字段而拒绝真实行程，也不把政策读取成功表述为全面合规认证。
- 证据不足、服务失败、候选不符合时间条件分别如实说明。未查全市场时，只说明本次候选中未找到方案。
- 正确识别实验工具返回的错误对象，允许预算内恢复；鉴权或格式等确定性错误不盲目重试，不通过伪造成功绕过失败。
- 当前实验入口的重试和到达日期过滤不属于七工具自身的保证：不能只迁移业务工具便宣称自动获得这些行为。重试仅由一个明确执行边界负责，避免模型、工具和请求层重试叠乘。实验入口默认最多三次重试及提前三十分钟只是实验默认值，不自动成为生产政策。
- 调整步骤和工具预算以容纳代表性流程。已有成功记录包含 10 项成功操作、13 次含重试尝试，此外还需最终结束调用；不得继续使用会必然截断此流程的旧上限。
- 预算仍必须有界；具体数值在实现中根据实际计数方式和超时配置确定。预算耗尽保留明确原因和 Trace，不保证任何外部故障都能恢复。

## Testing Decisions — 测试决策

主要验收入口复用现有 plan_trip，离线时在外部工具边界注入固定供应商结果，线上使用真实模型和真实 API。必要时补充少量字段转换合同验证，不为每个私有辅助函数建立测试层。用户已确认该入口安排，线上不要求固定航班或酒店。

测试外部行为：输入需求是否保留、输出是否有证据、是否按时到达、失败是否真实。沿用现有主链路测试、集成测试、独立 oracle 和 Trace 断言；新场景以语义条件验收，不固定线上候选 ID、酒店名称或价格。历史模拟案例保留历史定位，冲突规则不得继续作为新模式的验收依据。

### 必须满足的断言

1. 固定时钟为 2026-09-10，样例请求得到会议时间 2026-09-19 09:00，出行方式为飞机、前一日抵达、一晚住宿。
2. 样例 HU7386 在前一日 16:05 起飞、18:55 抵达，不得因旧 18:00 出发规则被拒绝；会议当天凌晨才抵达的候选不能满足提前一晚要求。
3. 住宿日期为 9 月 18—19 日；到达机场、酒店及会议地点之间必须使用相互吻合且有本次证据支持的地点与路线。
4. 酒店 08:00 出发、路线 942 秒，基础到达计算为 08:15:42；加入规划缓冲后仍须不晚于 09:00。将到达改成 09:01 必须拒绝可行结论。
5. 接驳费用未知不影响有证据的时间安排；输出不得把未知费用计为零或声称已获得完整行程总费用。
6. 改换会议地点、伪造航班时刻、引用未观察证据或以重复路线标识覆盖其他路线，必须被拒绝或正确隔离。
7. 航班前两次超时、第三次成功，酒店一次失败后成功的固定结果应能在配置预算内完成；持续失败或预算耗尽明确结束，不回退模拟数据。
8. 模型未按固定顺序调用不构成错误；缺少关键数据时可直接给出资料不足，无须强制执行没有输入条件的其他工具。
9. 真实联调至少覆盖一次从输入、模型调用、真实工具、结果校验到最终展示的成功链路。供应商失败时记录失败及缺口，不把离线通过替代线上通过。
10. 在不包含实验目录的隔离安装环境中，主链路工具能够导入、读取随包政策，并通过模拟外部响应完成业务链；配置、证据产物和资源不落回实验目录。迁移前后政策原文哈希一致，实验源码及资源未被改写。
11. 验证迁入版本保留当前酒店详情的供应商 ID 类型修正、地点候选上下文和路线接口兼容行为。业务工具调用、底层 HTTP 请求与重试分别计数，单个地点查询包含多个请求时不得漏记实际预算。

关键时间和证据断言在实现前确定。实现后至少做一次针对迟到判断的变异验证，确认错误条件确实导致失败，并以独立上下文进行针对时间衔接与证据篡改的对抗性复查。本文不声称已执行这些验证。

## Out of Scope — 不在范围内

- 最低价或最优路线推荐、自动排序策略、工具调用顺序优化。
- 政策文件内容调整、完整报销合规判断、职级及审批系统。
- 预订、支付、取消、实时库存保证和未来交通预测。
- 完整市内费用、早餐等费用计算，以及缺少起点地址时的杭州到机场接驳。
- 多人多房、多城市多晚、返程规划和通用多轮人工确认系统。
- 页面重做、并发服务架构优化、数据库迁移和无关模块重构。
- 为本次接入先行解决实验工具的全部长期限制。

## Further Notes — 补充说明

此前完整调用记录只证明当时实验工具能力，不证明现有主链路已完成集成，也不能替代当前重构版本的重新验证；真实 API 联调结果具有查询时效性。

本轮源码核查确认：实验二业务工具仅导入本地 Capture 和政策读取模块，Capture 使用本地配置；兼容入口转发至统一入口。到达日期过滤位于实验入口，实际条件为到达日不晚于指定住宿日，主链路仍须按用户要求核验前一日抵达，不能将该过滤当成完整行程校验。本轮仅更新规格，未运行线上工具或宣称新版本验收通过。
