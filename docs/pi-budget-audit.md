## 80k 是否包含命中、是否调整

**80,000 是一次用户请求所属 run 的累计用量，包含缓存命中的输入**。逐请求累加 `input + cacheRead + cacheWrite + output`；有原始用量时与 `prompt_tokens + completion_tokens` 交叉校验，reasoning 已在 output 中不重复加。命中改变价格，不从 token 预算扣除。它不是上下文窗口，也不是仅未命中 token。原始接口未独立报告 cache-write，本批规范化 cacheWrite=0 不能证明写缓存收费为零；中断未知用量不能填零。

初始预算本轮**不调整**：仍为 **模型 12 / 工具 20 / HTTP 30 / 累计 token 80,000 / 活跃 180 秒 / 单模型 45 秒**。完整工具覆盖回放最高 36,487，全部正式样本最高 49,196；80k 分别约为 2.19 倍、1.63 倍。最高样本乘 1.25 再加下一回答 4,096，token 需要 65,591，低于 80k；其他已测维度也未触限。工具尚漏记 SDK 前置拒绝，HTTP/时延是历史投影，不能据此保证未测在线流程必然够用。

## M03b 前的预算门禁

M01 实现受控配置、全尝试计量和前置预算预检，执行中不得自动加额。M04b 在正式 API/SSE 路径以完整覆盖三亚回放及三类改口各 3–5 次校准，并核对真实供应商查询计划、HTTP 与实际时延，不能以回放耗时估计线上耗时。

各维度最大样本乘 1.25 后必须小于等于配置；token 再加下一回答 4,096 预留。否则 M04b 阻塞 M03b，先修改对应受控配置，记录旧值/新值/样本依据并重测，不等到真实验收时才关闭预算。任意供应商失败或模型随机性仍可能触限；达到限制必须判失败，不能记三亚验收通过。

结论：现有完整工具覆盖回放不会被 80k 拦下；真实完整三亚尚无数据，当前不能保证其一定低于初始值。M04b 校准通过后才能进入 M03b，新在线实测须单独报告，不能用十二次累计或假模型 token 替代。
