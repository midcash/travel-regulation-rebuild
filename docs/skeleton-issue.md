# 骨架工单：一条真实航班查询走通 Pi 会话全链路

GitHub 工单：[#34](https://github.com/midcash/travel-regulation-rebuild/issues/34)，以工单正文为准；本文件是仓库内副本，随 PR 同步。旧 #11–#30 已关闭（not planned），由本单替代。行为依据：[product-behavior.md](product-behavior.md)；技术决定：[pi-migration-plan.md](pi-migration-plan.md)。

## 目标

用户在本机页面新建会话，发一句包含出发地、目的地和未来日期的航班查询。Python 通过 Node Pi SDK 1.3.0 调用真实交通工具，页面流式显示回答，以及带来源和查询时间的结果。刷新页面、重启服务后，能回到同一会话继续。本单只验这一条链路及其失败和恢复路径，不宣称 B01–B12 已完成。

## 范围内

- 一个启动命令、一个本地页面、一个会话服务；只绑定 127.0.0.1，校验 Host/Origin。
- Python 为每个会话管理一个 Node Pi 子进程。以 `verification/pi-step0/worker.mjs` 为基础改写成正式运行层，正式代码不导入 `verification`，不自写 Agent 循环。
- SQLite 是唯一存储：会话、消息（记录上海时间）、run、工具调用和结果证据、事件游标。先提交，再推给模型或页面。测试一律用临时库，不改旧表。
- API：创建/读取会话、发消息、读状态、SSE、取消。重复消息 ID 幂等，同 ID 不同正文拒绝；同一会话同时只跑一个 run，不同会话互不串内容。
- 只接航班查询工具。搜索参数只要城市和日期，去掉 `RealTools` 对旧 request 的依赖（会议时间、会场地点、固定两段路线、`meets_request`）。执行前重新检查日期不在过去。
- 工具返回精简事实、证据 ID、抓取时间和实际参数，原始结果不直接给模型或页面。保留现有输入校验、脱敏和 HTTP 上限。
- 模型没有文件、Shell、coding tools 的权限；供应商密钥只留在 Python。
- 缺凭证明确报错；供应商失败时保留消息和失败信息；不切演示数据，不下单。
- 重启时把未结束的 run 标为 interrupted，不自动重跑。
- 单次 run 硬上限：模型调用次数、工具调用次数、token 总量，默认值写在配置里，超限即停并记录原因。拿不到用量就记 unknown，不填零。

## 测试

- **白盒**：消息幂等和冲突、事务、取消、重启标 interrupted、跨午夜日期。断言状态和证据，不绑定回答措辞。
- **API 黑盒**：临时库、临时端口、固定时钟；只在模型传输和供应商 HTTP 边界用替身。覆盖正常查询、供应商失败、无凭证、SSE 重连、重复消息、取消、跨会话隔离。
- **浏览器冒烟（1 条）**：自动启停服务，创建会话 → 发消息 → 看到结果和来源 → 刷新 → 重启后仍可见。失败时保存截图和服务日志。
- **真实端到端**：单独命令，不进 CI。用 DeepSeek/途牛凭证和未来日期，记录输入、版本、用量、截图和供应商证据。缺凭证算未验收，离线结果不能冒充真实通过。
- **可复现**：新克隆按文档安装后，一个命令跑完全部免费检查；缺 Node、SDK 或浏览器时明确失败，不静默跳过。
