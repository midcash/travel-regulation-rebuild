# 实验三：中文交互式 Human-in-the-loop

## 最简单的启动方式

双击本目录的 **start.cmd**。它使用项目现有 `.venv`，不需要安装额外依赖。

也可以在 PyCharm 中直接运行本目录的 `cli.py`，不填参数。解释器选择项目 `.venv`。

在项目根目录的 PowerShell 中启动：

```powershell
.\.venv\Scripts\python.exe -X utf8 -B .\experiments\experiment_3_human_in_loop\cli.py
```

无参数进入中文菜单；原有 `start/status/resume/respond` 子命令继续输出 JSON，供脚本使用。

## 操作与验收

菜单中输入编号并回车，不需要复制任务 ID。

1. 选择“开始新任务”，再选择“选择交通和酒店”。
2. 交通选第 1 项，酒店选第 1 项。
3. 应显示总费用 **628 元**，预计 **07:50** 到场，校验通过。
4. 选择“确认方案”，应显示“方案已确认，任务完成”。

验证暂停恢复：新建任务后在等待节点输入 `0` 返回菜单，再输入 `0` 退出；重新双击启动，选择“继续已有任务”，按编号选中原任务。界面会恢复原来的人工请求。只有完整提交的选择会保存，输入了一半的选择退出后需要重选。

验证规则拦截：酒店选第 2 项，预计 08:10 到场，不能确认。选择“重新选择候选”，再选第 1 项酒店即可继续。也可以修改预算重新规划，或取消任务。

“查看运行记录”展示方案和事件；事件名保留英文，方便对照 runtime.py。等待有效期为 60 分钟，恢复或提交时检查过期，过期后请新建任务。没有后台过期扫描器。

## 本实验实际验证的内容

这是固定案例、离线数据驱动的状态机，不调用真实模型、供应商 API，不预订或付款。日期固定为 2026-09-12，价格和路线仅用于教学。业务校验目前只覆盖模拟总预算和到场时间，不代表完整差旅法规校验。

- 查询候选 → 持久化等待 → 人工选择 → 查询模拟详情 → 等待确认 → 完成。
- 人工请求、回复、运行快照及事件均存于本目录 `artifacts/hil.sqlite3`。
- 界面等待 input() 时没有打开数据库事务，业务执行已经暂停。
- 同一离线状态迁移在 SQLite 事务中提交；异常或进程终止前未提交的迁移由 SQLite 回滚，重试原回复即可。
- 对旧版本遗留的“回复 consumed、运行仍等待”记录，继续任务会从保存的回复恢复。
- 同一回复 ID 重复提交不会重复推进；同一 ID 携带不同内容会被拒绝。
- 过期检查会同时持久化人工请求和运行的 expired 状态。

`resume` 现在能恢复上述旧记录和未完成的离线执行；正常等待时返回人工请求，终态返回当前结果。

## 学习取舍

本轮选择标准库中文菜单，不实现复杂终端渲染或自由对话。这样可以集中观察人工决策与状态变化。

事务覆盖整个离线迁移是为了简单、可验证。接入真实模型或网络工具时，不应持有数据库写锁等待网络：需要拆成短事务、持久化待执行动作、执行结果检查点及重试/幂等控制。本实验尚未验证真实外部副作用的 exactly-once 执行。

没有模型消息历史、Token 预算、多用户权限和后台调度。`tool_calls` 是模拟流程计数，不能作为“不发生任何重复外部调用”的证明。后续集成主链路应单独设计这些能力。

## 文件阅读顺序

1. `interactive.py`：菜单、候选选择、方案确认、保存退出。
2. `cli.py`：交互模式与原命令模式的入口。
3. `runtime.py`：状态机、事务、人工请求、恢复和过期。
4. `test_runtime.py`、`test_interactive.py`：基础流程、异常回归、跨进程 CLI 操作。

运行全部测试（项目根目录）：

```powershell
.\.venv\Scripts\python.exe -X utf8 -B -m unittest experiments.experiment_3_human_in_loop.test_runtime experiments.experiment_3_human_in_loop.test_interactive -v
```

测试临时目录位于实验三内，结束后清理；`-B` 禁止生成字节码。本轮验证为 14 个测试通过，包含真实 CLI 子进程的完整交互、退出后继续、旧命令兼容以及故障注入。没有通过测试宣称完整生产可靠性。
