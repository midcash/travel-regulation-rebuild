# 第 18 章 · Agent 项目上线问题

> 对应原文：顶层 `07-Agent开发框架与工程实践.md` 第 18 章
> 对应原型：`p18_online_ops/`

## 形状

```text
上线前有基线
   ↓
线上 Trace（模型/Prompt/工具/状态/结果/反馈）
   ↓
业务质量 + 延迟/成本 + 安全合规
   ↓
漂移告警 → 定位模型、Prompt、RAG、工具或数据 → 修复/回滚/补评测
```

## 知识点总括

- 上线后监控不能只看服务可用率和 HTTP 200，要看任务结果、用户反馈、工具成功率、延迟、成本和安全。
- 线上通常缺少即时标准答案，因此要与离线基线或历史窗口比较，监控漂移而不是假装有绝对正确率。
- Trace 至少要关联模型版本、Prompt 版本、工具调用、失败阶段、token/cost、延迟、fallback 和人工/用户反馈。
- 归因要先判断发生在模型、Prompt、RAG、外部工具还是安全策略，不能把所有问题都归因到模型。
- 修复闭环包括回滚、灰度、熔断/降级、补充评测样本、修复依赖和更新发布闸门。
- 安全项按自己的分母做一票否决，不能被整体平均分稀释。
