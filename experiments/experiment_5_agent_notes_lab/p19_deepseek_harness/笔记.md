# 第 19 章 · DeepSeekHarness

> 对应原文：顶层 `07-Agent开发框架与工程实践.md` 第 19 章
> 对应原型：`p19_deepseek_harness/`

## 形状

```text
Profile / Bundle / Patch
          ↓
Loader → Registry → Fiber → Context 服务槽
          ↓
模型 + AgentLoop + 工具 + Session + Sandbox + UI
          ↓
append-only SessionEventLog → 派生消息/恢复/回放/审计
```

## 知识点总括

- DeepSeekHarness 是可直接运行的 Agent，也是可重组的 Agent Runtime；`Agent = LLM + Harness`。
- 宏观主线仍是入口 → AgentLoop → LLM/工具循环 → 会话持久化，但它把主要能力都纳入 Cordis 插件体系。
- Loader 找插件和配置，Registry 管理插件/Fiber，Fiber 托管单个插件实例，Context 访问服务，Effect 清理副作用。
- 响应式依赖负责服务变化的传播，HMR 负责代码/配置变化后的替换；二者都要求旧实现干净卸载。
- append-only SessionEventLog 不是旁路日志，而是会话唯一事实来源；消息历史、Trajectory、恢复、Fork 和 Replay 都应该由事件流派生。
- “模型可见即已记录”意味着影响模型决策的输入必须可以从事件日志重建，避免运行状态和审计日志分裂。
- 插件化仍需要服务接口、Registry、事件和 UI Slot 等约定，并不意味着任意代码都能无约束接入。

## 反直觉点

1. AgentLoop 也可以是插件，不是插件外面永远固定的核心。
2. HMR 不是把旧对象覆盖掉；必须处理依赖、状态和副作用清理。
3. EventLog 不是“顺便记日志”，而是唯一事实；消息数组是从事件派生的投影。

先运行 `main.py`，再打开 `workspace/session-events.jsonl` 对照事件序列。
