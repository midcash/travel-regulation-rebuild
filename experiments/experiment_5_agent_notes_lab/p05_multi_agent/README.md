# p05 Multi-Agent 架构与通信

**对应笔记**：第 6 章（含 Google《Towards a Science of Scaling Agent Systems》的结论）

## 一句话结论

**多 Agent 不一定比单 Agent 好。** 在强顺序、长推理链、单体基线已经不错、
工具密集且预算固定的场景下，盲目上多 Agent 反而掉性能。

这个原型的价值在于：把"某架构更好"这句话变成一张**带数字的表**。

## 演示 1 的实测数字（子 Agent 错误率统一 25%，各跑 4000 次）

| 架构 | 最终错误率 | 错误放大 | LLM 调用 | 通信消息 | token | 顺序深度 |
|---|---|---|---|---|---|---|
| SAS 单体 | 24.7% | 0.99x | 3.0 | 0 | 900 | 3 |
| 独立多体（分工拼装） | **56.5%** | **2.26x** | 6.0 | 3 | 2100 | 2 |
| 独立多体（同任务投票） | 15.2% | 0.61x | 6.0 | 3 | 2100 | 2 |
| 中心化（主管编排） | 26.7% | 1.07x | 4.6 | 7 | 3674 | 3 |
| 去中心化（点对点辩论） | 4.4% | 0.17x | 9.0 | 15 | 5400 | 3 |
| 混合（层级+有限对等） | 16.9% | 0.68x | 4.7 | 5 | 3722 | 4 |

**「错误放大」= 最终错误率 ÷ 单个子 Agent 的错误率。**
大于 1 = 架构在放大错误，小于 1 = 架构在吸收错误。

> **这四个指标是怎么来的**：`架构运行时的每一次 LLM 调用、每一条 Agent 间消息，
> 都由 `architectures.Ledger` 记一笔**数出来**；`correct` 由 4000 次试验统计。
> 表格里没有手写常量 —— 你改流程，这一列会跟着变。
> 唯一允许假设的是**单位成本**（一次调用多少 token），它是参数，写在 `Ledger(tokens_per_call=...)` 里。

读这张表的三个要点：

1. **分工拼装 2.26x** —— 这是错误放大最严重的拓扑。每个子任务各自完成再拼装，
   任意一块错了整体就错，错误被叠加。
2. **同任务投票 0.61x** —— 名字都叫 Independent，结论完全相反。
   投票用集体决策把个体幻觉抵消掉了。
3. **中心化 1.07x vs 分工拼装 2.26x** —— 拓扑一样（都要求每个子任务都对），
   差别只在主管有没有**验收门控**。这一环值一半的错误率。

## 三个容易被面试问倒的点

### 1. 中心化并没有把错误率压到 0

子任务越多，`每个都必须对` 这个连乘就越吃亏。所以主管要控制并行窗口的规模，
而不是把任务切得越碎越好。

### 2. 委派省的不是钱，是上下文

演示 4-b：子 Agent 折腾了 4 条消息 88 token，回到主管上下文的
**只有 1 条 tool_result、27 token**。主管上下文 62 → 89。

子 Agent 在私有空间里折腾多久都行，这是委派和移交最大的区别。
落地形式就是**把子 Agent 包装成一个普通工具**（`ask_退款核查`），
对主循环来说它和 `search`、`calculator` 没有任何区别。

### 3. 消息协作的通信税是 O(N²)

3 个 Agent 两轮就是 12 条消息。笔记提醒：这种拓扑通常要加通信限流/白名单。

## 三种通信模式

| 模式 | 控制权 | 上下文 | 典型实现 |
|---|---|---|---|
| 移交 Handoff | 完整转移，交棒方退出 | 整体带走 | 接力跑交棒 |
| 工具调用 ToolCall | 主管保留 | **只收回最终结果** | Claude Code 的 SubAgent |
| 消息协作 | 分散在各 Agent | 持续交换 | Claude Code 的 AgentTeam |

介质也是设计的一部分：委派用**内存通道**（同步返回），
协作用**文件邮箱**（落盘等着，接收方不在线也不丢）。

## 传什么（演示 5）

| 做法 | token | 相对开销 | 代价 |
|---|---|---|---|
| 共享完整推理数据 | 114 | 100% | 状态空间快速膨胀 |
| 只共享最终结果 | 22 | **19%** | 必须为每个 Agent 定义清晰的结果模式 |

笔记的措辞：由外部框架构造新的上下文，**只传递必要的消息、工具参数和任务产物**，
而不是默认共享全部内部状态。

## 建议打断点的地方

1. `architectures.py` 里 `run_centralized` 的
   `if not ok and rng.random() < gate_catch_rate:`
   → **压制错误放大的那一行**就是它
2. `architectures.py` 里 `amplification=error_rate / per_agent`
   → "错误放大"的定义
3. `communication.py` 里 `delegate()` 的 `orchestrator.messages.append(tool_result)`
   → 委派模式下回到主管上下文的只有这一行
