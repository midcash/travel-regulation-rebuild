# 第 16 章 · 面试官压力项目应对方案

> 对应原文：顶层 `07-Agent开发框架与工程实践.md` 第 16 章
> 对应原型：`p16_agentic_boundary/`

## 形状

```text
Agentic 程度 = 决策权在谁手里 + 反馈闭环 + 目标完成判断

路径确定/高风险 ──→ Workflow 或混合系统
路径开放/低成本试错 ─→ 有护栏 Agent
```

## 知识点总括

- Agentic 的核心不是“是否用了大模型”，而是控制流、工具选择和下一步决策是否由模型在运行时决定。
- 核心四项：动态决定下一步、自主调工具、根据反馈修正、有目标感；加分项：反思进化、跨会话记忆、自恢复、知道何时问人。
- 护栏、预算、审批不是 Agentic 的反面；有实权还知道何时被管住，才是可生产的 Agent。
- Workflow 仍属于 Agentic System 的一种架构形态。应按路径是否确定、验证是否容易、失败代价是否高来选。
- 是否使用 Agent 要看三条：需要判断而不是查表、规则已经难维护、输入大量非结构化。
- 规则成本随情况种类增长，模型成本随调用次数增长；现实中常用分层：规则处理大多数、LLM 处理长尾或离线学习。
- 多步系统存在复合错误率，因此窄域/高风险任务主动收窄自主性是工程正确性。

运行 `main.py`，观察固定 Workflow 和自适应 Agent 在缺少出发地时的控制流差异。
