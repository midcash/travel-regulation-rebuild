# 第 11 章 · OpenClaw

> 对应原文：顶层 `07-Agent开发框架与工程实践.md` 第 11 章
> 对应原型：`p11_openclaw/`

## 形状

```text
Messages / Heartbeats / Crons / Hooks / Webhooks
                 ↓
Gateway：认证、协议转换、session 路由（不调 LLM、不执行工具）
                 ↓
Agent：Think → Act → Remember → 最终回复
                 ↓
SessionTranscript + Workspace Memory + RetrievalIndex
```

## 知识点总括

- OpenClaw 是本地自托管、事件驱动的个人 AI 助手；“看起来主动”来自心跳和 Cron，“看起来记得”来自持久化记忆与按需检索。
- 触发层有五类信号：用户消息、周期心跳、计划任务、内部生命周期 Hook、外部 Webhook。
- Gateway 是多渠道适配器、路由器和安全网关。它的关键边界是：不推理、不调模型、不执行工具。
- Agent 层采用 ReAct：模型决定直接回复还是选工具，工具执行结果回灌上下文，再继续决策。
- 记忆可以拆成 BootstrapFiles、SessionTranscript、ContextWindow、RetrievalIndex；长期记忆要写入文件，检索通常是 `memory_search → memory_get`。
- 强系统能力必须配权限、隔离账号、工具 allowlist、日志和人工确认；能力越强，Prompt Injection、恶意插件、凭证泄露和命令误解的影响越大。
- 多 Agent 可采用递归 Centralized：父 Agent 负责最终回复，子 Agent 私有执行，只把蒸馏后的最终结果异步推回父 Agent，避免上下文膨胀。

## 代码对照

| 笔记概念 | 代码形状 | 容易漏掉的点 |
|---|---|---|
| 事件驱动 | `TriggerLayer.emit()` | 触发源不等于执行逻辑 |
| Gateway | `Gateway.ingest()` | 路由层不应偷偷调用 LLM |
| 按需记忆 | `memory_search` / `memory_get` | 全量塞入上下文会浪费 token |
| 安全边界 | `SecureToolRunner.allowlist` | “模型想调用”不等于“系统允许调用” |
